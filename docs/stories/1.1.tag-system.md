## Story

**As a** operador do WhatsFlow,
**I want** gerenciar tags (criar, editar, remover, atribuir cores e categorias) e associa-las aos meus leads/contatos,
**so that** eu possa classificar leads de forma permanente (CRM) e usar essas tags como criterio de filtragem no Inbox.

## Acceptance Criteria

1. Existe uma tabela `tags` com campos: `id` (uuid), `name` (unique), `color` (hex), `category` (enum: 'lead_status' | 'segment' | 'custom'), `created_at`, `updated_at`
2. Existe uma tabela `contact_tags` (junction) com campos: `id`, `contact_id` (FK contacts), `tag_id` (FK tags), `created_at`, com unique constraint em (contact_id, tag_id)
3. API `GET /api/tags` retorna lista completa de tags com contagem de contatos associados
4. API `POST /api/tags` cria tag com validacao (nome unico, cor hex valida, categoria valida)
5. API `PATCH /api/tags/[id]` atualiza tag (nome, cor, categoria)
6. API `DELETE /api/tags/[id]` remove tag e suas associacoes em `contact_tags` (cascade)
7. API `PUT /api/contacts/[id]/tags` permite associar/desassociar tags a um contato (recebe array de tag_ids, faz sync)
8. No painel "Contexto do Contato" (sidebar direita do Inbox), tags do contato sao exibidas como badges coloridas com opcao de adicionar/remover
9. Existe uma tela/modal de gerenciamento de tags acessivel via Configuracoes ou via icone no Inbox, com CRUD completo (criar, editar cor/nome, deletar)
10. Indices criados: `idx_contact_tags_tag` em `contact_tags(tag_id)`, `idx_contact_tags_contact` em `contact_tags(contact_id)`
11. Migration Supabase criada e funcional (rollback seguro)

## Dev Notes

### Arquitetura de Referencia
- **Padrao existente para labels:** `lib/inbox/inbox-db.ts`: funcoes de CRUD para `inbox_labels` e `inbox_conversation_labels`
- **Service layer:** `services/inboxService.ts`: seguir mesmo padrao (fetch wrapper com error handling)
- **Hooks:** `hooks/useLabels.ts`: seguir padrao React Query (staleTime: 30s, gcTime: 5min)
- **Componentes:** `components/features/inbox/`: seguir padrao de componentes existentes
- **UI lib:** shadcn/ui (new-york style) + Tailwind CSS v4 + lucide-react icons

### Diferencas Tags vs Labels
- `inbox_labels` = etiquetas de **conversa** (contexto temporario, ja existente)
- `tags` = classificacao do **lead/contato** (permanente, CRM, NOVO)
- Ambos coexistem, tags aparecem no Contexto do Contato, labels aparecem na conversa

### Database
- Usar `getSupabaseAdmin()` nas API routes (server-side, bypass RLS)
- Migration em `app/supabase/migrations/`
- Pattern de naming: `YYYYMMDDHHMMSS_description.sql`

### Testing
- Testar CRUD completo via API routes
- Testar cascade delete (remover tag deve limpar contact_tags)
- Testar unique constraint (mesmo contact+tag nao duplica)
- Testar validacao Zod (nome vazio, cor invalida, categoria invalida)
