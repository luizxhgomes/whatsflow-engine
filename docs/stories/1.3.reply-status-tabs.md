# Story 1.3: Reply Status Tabs

## Status
InProgress

## Estimate
S (Small)

## Scope
**IN:** Campo `reply_status` em `inbox_conversations`, auto-update atomico no createMessage, tabs UI com contadores, indicador visual no conversation item, backfill de dados existentes
**OUT:** Notificacoes push para mensagens nao respondidas, auto-assign baseado em reply status, SLA tracking por tempo de resposta

## Risks
- Backfill SQL em tabela grande pode impactar performance — mitigacao: executar em batches com LIMIT ou em horario de baixo trafego
- Conversas sem mensagens (edge case) ficam com reply_status indefinido — mitigacao: default 'unreplied' na coluna

## Story

**As a** operador do WhatsFlow,
**I want** ver as conversas do Inbox separadas por "Nao Respondidas" e "Respondidas" em tabs/abas,
**so that** eu possa priorizar rapidamente os leads que aguardam minha resposta e organizar meu fluxo de atendimento.

## Acceptance Criteria

1. Coluna `reply_status` (TEXT, enum: 'replied' | 'unreplied', default 'unreplied') adicionada em `inbox_conversations`
2. Indice criado: `idx_conv_reply_status` em `inbox_conversations(reply_status, status)`
3. Quando uma mensagem **inbound** (lead envia) e registrada, `reply_status` e atualizado para `'unreplied'`
4. Quando uma mensagem **outbound** (bot ou humano responde) e registrada, `reply_status` e atualizado para `'replied'`
5. A atualizacao de `reply_status` e atomica (dentro da mesma transacao de `createMessage`)
6. API `GET /api/inbox/conversations` aceita query param `replyStatus` com valores: `replied`, `unreplied`, `all` (default: `all`)
7. UI exibe tabs acima da lista de conversas: "Nao respondidas (N)" | "Respondidas (N)" | "Todas"
8. O contador em cada tab reflete quantidade real de conversas abertas naquele status
9. Tab "Nao respondidas" e a tab ativa por padrao ao abrir o Inbox
10. Tabs funcionam em conjunto com os filtros existentes (status, mode, labels) e os filtros avancados da Story 1.2
11. Indicador visual (bolinha/dot colorida) na conversation item para diferenciar respondida/nao respondida na lista

### Backfill Strategy
Para conversas existentes, rodar SQL de backfill na migration:
```sql
UPDATE inbox_conversations c SET reply_status =
  CASE WHEN (
    SELECT direction FROM inbox_messages
    WHERE conversation_id = c.id
    ORDER BY created_at DESC LIMIT 1
  ) = 'inbound' THEN 'unreplied' ELSE 'replied' END
WHERE reply_status IS NULL;
```

### Tab Counters
- Opcao A: Query separada com `COUNT(*)` agrupada por `reply_status` (mais eficiente)
- Opcao B: Derivar do resultado filtrado (menos uma query, mas recalcula a cada filtro)
- **Recomendacao:** Opcao A — RPC function `get_reply_status_counts(filters)` que retorna counts
